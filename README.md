# FANZONE

Платформа совместного просмотра: одна комната, один источник, общий чат.

Зритель создаёт комнату, вставляет источник, который ему разрешено показывать, и отправляет ссылку. Все, кто открыли её, попадают в ту же комнату — не в копию.

## Что уже работает

- Создание публичной или приватной комнаты, необязательный пароль, ссылка вида `/room/ab12cd34`.
- Общий чат, реакции, вход и выход, счётчик зрителей, история до 200 сообщений и 48 часов.
- Плеер: HLS через hls.js (или нативно в Safari), MP4/WebM/OGG, встраивание YouTube, Twitch, Vimeo и Dailymotion.
- Ведущий меняет источник и режим без новой комнаты. В синхронном режиме пауза и перемотка записи передаются зрителям. Для прямого эфира одинаковая секунда не гарантируется.
- Права ведущего проверяются на сервере по секрету, а не по галочке из браузера.
- После обновления страницы вход в ту же комнату восстанавливается. При обрыве сети клиент переподключается сам.

Демонстрационные матчи на главной — это макет расписания, не результаты и не живые трансляции. Спортивный API не подключён.

## Запуск

```bash
npm run dev
npm run typecheck
npm test
npm run build
```

База поднимается сама: в разработке это встроенный Postgres, в публикации — Neon, если задан `DATABASE_URL`. Схему описывают файлы в `migrations/`. Файл `.env` в репозиторий не кладётся: строка подключения и секреты задаются окружением хостинга.

Проверка готовности: `GET /api/health` отвечает `{ "ok": true, "service": "fanzone" }`.

## Реальное время

Чат и плеер синхронизируются через журнал комнаты на сервере. Клиент забирает актуальное состояние примерно раз в секунду и сразу после своих действий. Так комната работает и на serverless-хостинге, где долгий WebSocket-процесс недоступен.

Контракт события один: снимок комнаты (источник, режим, пауза, позиция, сообщения, зрители). Постоянный Socket.IO-адаптер может публиковать тот же снимок, не меняя плеер и чат:

```js
io.to(roomCode).emit("room", snapshot);
socket.on("playback", (payload) => savePlayback(roomCode, payload));
```

Пока адаптер не включён, источником правды остаётся база, а не соединение конкретного процесса.

## Источники

Сервер не скачивает и не проксирует чужие потоки. Браузер зрителя открывает ссылку сам.

- HLS — только публичный `https` и манифест `.m3u8`. Ошибки сети, CORS и битого манифеста показываются в плеере.
- Файл — `https` и окончание `.mp4`, `.webm` или `.ogg`.
- iframe — только YouTube, Twitch, Vimeo, Dailymotion. Другие домены отклоняются.
- Внутренние адреса, `blob:` и `file:` для общего источника запрещены.

В форме источника есть тестовый HLS-ролик Apple. Это не спортивная трансляция, а проверка плеера.

## Ace Stream

Если указан только идентификатор, плеер показывает инструкцию и не изображает работающий эфир.

1. Установите Ace Stream Engine и запустите его.
2. В плеере укажите локальный шлюз, например `http://127.0.0.1:6878`. Адрес хранится в браузере этого зрителя.
3. Либо ведущий сохраняет общий HTTPS-шлюз в источнике комнаты.
4. Плеер запрашивает `{шлюз}/ace/manifest.m3u8?id={contentId}`.

Если движок отдаёт только MPEG-TS (`/ace/getstream`), браузер такой поток не воспроизведёт. Нужен шлюз, который превращает его в HLS. FANZONE этот поток сам не конвертирует.

## Публикация

Приложение собирается как серверный React-проект и рассчитано на хостинг вроде Vercel. HTTPS там включается платформой. Для собственного сервера нужен обратный прокси с TLS и переменная `DATABASE_URL`.

Docker-образ не является основным способом публикации: сборка заточена под serverless-вывод, а не под отдельный Node-процесс. Локально достаточно `npm run dev` и `npm run build`.

Приватные комнаты не попадают в общий список. Пароль и ключ ведущего хранятся только в виде хеша.
